SECTION: ETL PIPELINE — TECHNICAL NOTES
================================================================================

Pipeline: extract → transform → load (async Lambda-to-Lambda)
Trigger:  EventBridge rule "trip-me-buddy-etl-nightly" at 02:00 UTC (currently DISABLED)
Source:   RDS tripmebbuddy_v2 → S3 staging → Redshift Serverless tripmebuddy_analytics

Tables loaded into Redshift:
  fact_trips          — core trip records (TRUNCATE + COPY)
  dim_users           — user records (TRUNCATE + COPY)
  dim_destinations    — destination records (TRUNCATE + COPY)
  dim_flights_hotels  — flight/hotel records (TRUNCATE + COPY)
  dim_exchange_rates  — daily FX rates (APPEND ONLY — historical accumulation)
                        Source: api.exchangerate-api.com/v4/latest/USD (~166 currencies, base USD)
                        Load strategy: DELETE current date's rows, then COPY — preserves history

Known issue resolved (2026-03-03):
  Frankfurter API (api.frankfurter.app) returned HTTP 403 from Lambda IP ranges.
  Switched to exchangerate-api.com (same API used by backend CurrencyService).

Lambda configs:
  extract:   timeout=300s, memory=512MB, handler=extract.handler
  transform: timeout=300s, memory=512MB, handler=transform.handler
  load:      timeout=900s, memory=512MB, handler=load.handler (long for Redshift cold start)

Redshift cold start: first query of the day takes 35–40s (serverless auto-resume).
Load lambda polls every 5s × 120 iterations = 600s max per SQL statement.

SECTION: POWER BI — CONNECTION NOTES
================================================================================

Connection type: Amazon Redshift (Npgsql driver)
Server: localhost:5439  (via SSH tunnel through bastion EC2)
Database: tripmebuddy_analytics
Username: admin

Prerequisites:
  1. Start bastion EC2 (instance ID in etl.tfvars)
  2. Open SSH tunnel:
     ssh -i ~/.ssh/ec2_trip_me_buddy.pem \
       -L 5439:<redshift-workgroup-endpoint>:5439 \
       ec2-user@BASTION_IP -N
  3. In Power BI: File → Options → Data source settings → clear cached credentials before reconnecting.

Known issue: "Failed to enable constraints" error on import.
Fix: Use Value.NativeQuery with explicit SELECT instead of direct table load.
Example M query:
  let
    Source = AmazonRedshift.Database("localhost:5439", "tripmebuddy_analytics"),
    db = Source{[Name="tripmebuddy_analytics"]}[Data],
    schema = db{[Name="public"]}[Data],
    result = Value.NativeQuery(schema, "SELECT col1, col2 FROM fact_trips", null, [EnableFolding=false])
  in result

SSL requirement: Redshift enforces SSL + SCRAM-SHA-256.
  Do NOT click OK on "Encryption Support" dialog — it tries unencrypted fallback which breaks SCRAM auth.
  If auth fails: clear credentials in File → Options → Data source settings, then reconnect fresh.
